# 顾客端 V1 原项目审计

> 审计日期：2026-08-17
> 审计范围：当前仓库、当前分支代码、微信开发者工具本地运行态、生产公网只读检查
> 安全边界：未读取或记录密钥；未修改生产服务器、生产数据库或生产配置。

## 1. 项目技术栈

- 小程序：微信原生 JavaScript / WXML / WXSS，当前开发入口为 `miniapp/`。
- 后端：Go 标准库 `net/http`，应用代码位于 `backend/internal/app/`。
- 持久化：MySQL 8.x + Redis 7.x；内存模式用于本地开发，持久化初始化和列补齐由后端完成。
- 管理后台：Vue 3 + Vite + TypeScript，位于 `admin/`。
- 部署：Docker Compose + Nginx，持久化模板位于 `deploy/`。
- 运行形态：同一微信小程序 AppID，同时承载顾客端和员工端；员工入口从顾客端“我的 → 店长入口”进入。

## 2. 当前系统架构

```text
微信小程序 miniapp/
  顾客 Tab：首页 / 款式 / 门店 / 我的
  顾客分包：商品详情 / 门店详情 / 创建预约 / 我的预约 / 预约详情 / 回收介绍
  员工页面：登录 / 工作台 / 商品 / 库存 / 订单 / 会员 / 门店 / 员工预约管理
          │ utils/request.js + customer-auth.js
          ▼
Go API backend/
  顾客公开接口 /api/v1/customer/*
  顾客会话接口 /api/v1/customer/*（顾客 token）
  员工/管理接口 /api/*、/api/admin/*（员工 token + 后端权限）
          │
          ▼
MySQL / Redis（persistent）或内存 Store（memory/dev）
```

当前代码已经把顾客首页作为首屏，原员工页面仍保留；顾客端不通过隐藏按钮获得员工数据，员工管理接口仍由后端中间件校验。

## 3. 前端页面清单

### 顾客主包

- `pages/customer-home/index`：顾客首页、轮播、最近门店、预约入口。
- `pages/customer-products/index`：款式/商品列表。
- `pages/customer-stores/index`：门店列表、定位、距离、电话、导航、预约。
- `pages/customer-mine/index`：我的预约、回收介绍、隐私、店长入口。
- `pages/customer-privacy/index`：顾客隐私说明。

### 顾客分包 `pkg-customer`

- `product-detail/index`、`store-detail/index`。
- `appointment-create/index`、`appointments/index`、`appointment-detail/index`、`appointment-notes/index`。
- `recycle-info/index`。

### 原员工页面

登录、工作台、订单、订单详情、跟踪、会员、商品、库存、耗材、商品详情/表单、员工资料、门店信息、员工预约、预约详情、法律页面均仍在 `miniapp/pages/` 中注册。

## 4. 后端模块清单

- `app.go`：配置、路由、中间件、请求上下文、CORS、持久化运行时校验。
- `handlers.go`：原收银、订单、员工工作台相关接口。
- `customer_handlers.go`：顾客首页、商品、门店、预约、顾客会话和错误码映射。
- `admin_customer_handlers.go`：首页配置、Banner、商品扩展、门店顾客配置、预约管理、上传相关后台接口。
- `customer_store.go`：顾客会话、浏览数据、预约状态机及预约持久化一致性。
- `admin_customer_store.go`：后台配置和后台预约操作的数据层。
- `persistence.go` 等：MySQL/Redis 持久化、初始化、列补齐和资源关闭。
- `auth.go` / `middleware.go` 等：员工 token、角色、权限和门店可见范围校验。

## 5. 数据表清单

以当前 Go 类型、持久化初始化和列补齐代码为准，已确认使用或扩展的实体包括：

- 员工账号、角色、权限、员工-门店关系。
- 顾客微信会话、顾客资料（openid、手机号等）。
- 门店及顾客展示扩展（地址、电话、图片、服务标签、预约开关、经纬度、排序）。
- 商品、商品分类、商品图片和款式/工费展示扩展。
- 首页配置、Banner、上传资源。
- 预约规则、顾客预约、预约备注/员工备注、预约操作审计。
- 原员工端业务实体：订单、订单明细、会员、库存、耗材、支付/收银相关历史实体。

具体 SQL 表名以 `persistence.go` 和迁移/初始化代码为准；本节点没有执行迁移，也没有把推断表名写成接口契约。

## 6. 登录与权限现状

- 顾客身份：微信登录换取顾客 token；手机号授权后，后端以顾客资料中的已验证手机号为预约联系号码。
- 员工身份：账号密码登录，使用员工 token、角色和权限访问工作台/管理接口。
- 同 AppID 不等于同权限：顾客 token 不应通过任何员工 handler；后端 `withAuth`、角色/权限和门店范围校验是安全边界。
- 当前代码已补上预约手机号后端校验：未验证手机号返回 40310，不能只依赖前端输入。
- 当前代码已补上持久化失败回滚：预约创建、取消、备注和员工状态操作在写库失败时不返回成功，并映射 50302。

## 8. 必须改造或持续完善的能力

- 生产环境必须使用明确的 `CORS_ORIGIN`、非默认 `TOKEN_SECRET`、真实微信 AppID/Secret，并关闭 mock login；后端现在会在 persistent 模式启动时 fail-fast。
- 生产 Nginx 必须完成 HTTPS 强制跳转和证书配置；本次只更新了持久化配置模板，没有改生产服务器。
- 后台必须补齐每个营业门店的真实电话、经纬度、图片和首页 Banner；代码不能猜测这些业务数据。
- 微信真机必须验证真实登录、手机号授权、定位授权、地图导航、预约创建/取消和员工登录隔离。
- 生产发布必须补充数据库备份、恢复演练、版本记录和回滚证据。

## 9. 数据安全风险

- 生产公网当前只读检查仍显示 CORS `*`；旧实例未部署本次后端收紧逻辑。
- HTTP 域名当前未跳转 HTTPS，存在传输安全和微信审核风险。
- 生产数据配置不完整会导致错误导航、无电话联系、首页空 Banner；不得以假坐标或假资源兜底为商用数据。
- 顾客 token 与员工 token 必须持续做接口隔离回归；前端隐藏员工入口不能替代后端鉴权。
- 持久化写失败若被吞掉会造成“接口成功、数据库未写入”；本次已统一预约写入出口并回滚内存状态。

## 10. 微信审核和隐私风险

- `getLocation` 已声明用途文案“用于查找附近的门店”，需在真实 AppID 隐私配置、页面触发时机和隐私协议中保持一致。
- 手机号授权仅用于门店联系确认，需真机验证授权按钮、拒绝分支和服务端换取手机号流程。
- 地图导航依赖有效经纬度；生产门店坐标为 0 时必须禁用导航并提示，不得调用 `wx.openLocation`。
- 同 AppID 承载顾客端和员工端需要确认服务类目、隐私说明、店长登录入口文案与提审体验路径一致。

## 11. 外部依赖

## 12. 当前 P0/P1/P2 问题

### P0

- 生产发布闸门未满足：公网旧实例仍是 wildcard CORS、HTTP 未强制 HTTPS、生产首页/门店内容不完整；因此整体仍不能宣布商用交付。
- 未经授权不能通过本地操作代替生产部署、生产数据录入或微信真机授权验收。

### P1

- 生产门店坐标为 0，无法可靠完成最近门店和地图导航。
- 生产首页 Banner 数量为 0，生产图片资源存在 404。
- 真实微信登录、手机号授权、定位授权、生产持久化、备份恢复和员工账号隔离尚未形成真机/生产证据。
- 生产 CORS/HTTPS 需要运维部署本次模板和配置。

### P2

- 微信开发者工具有一个平台 preload warning；当前问题计数为 0，未发现业务 JS 异常。
- 开发者工具首次切换 tab 可能需要等待懒加载渲染，验收脚本应等待页面路径和页面文本稳定后再判定。
- `miniapp-customer/` 等历史快照不得作为新的上传源；当前统一开发源是 `miniapp/`。
