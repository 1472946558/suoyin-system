# 09 - 隐私合规文档

## 1. 微信位置权限

### 1.1 使用目的

获取顾客当前位置，用于计算与各门店的距离，推荐最近门店。顾客位置仅在小程序内存中计算，不上传服务器，不落库。

### 1.2 权限声明

**app.json 需添加：**
```json
{
  "requiredPrivateInfos": ["getLocation"]
}
```

### 1.3 授权流程

1. 顾客进入门店列表页或预约页时，调用 `wx.getLocation`
2. 系统弹出位置授权弹窗
3. 顾客授权 → 获取经纬度 → 计算距离 → 推荐最近门店
4. 顾客拒绝 → 提示"未获取位置，无法按距离排序" → 允许手动选择门店

### 1.4 降级策略

- 拒绝授权：不阻断使用，门店列表不按距离排序
- 位置获取失败：同拒绝授权处理
- 门店无经纬度：该门店不参与距离计算

## 2. 手机号授权

### 2.1 使用目的

获取顾客手机号，用于预约联系。手机号通过微信手机号能力获取，不手动输入。

### 2.2 授权流程

1. 顾客提交预约时，检查是否已授权手机号
2. 未授权 → 显示 `<button open-type="getPhoneNumber">` 按钮
3. 顾客点击授权 → 获取 phoneCode
4. 后端调用微信 `getuserphonenumber` 接口换算手机号
5. 更新顾客档案

### 2.3 脱敏展示

- 顾客"我的"页面：手机号脱敏显示（138****1234）
- 预约列表：不显示手机号
- 预约详情：脱敏显示
- 员工端预约管理：完整显示（业务需要）

### 2.4 安全要求

- 手机号在后端存储为明文（业务需要）
- 顾客端 API 返回脱敏手机号
- 员工端 API 返回完整手机号（需权限校验）

## 3. 隐私协议需要补充的内容

### 3.1 隐私协议文案

需要在微信小程序后台「用户隐私保护指引」中补充：

```
1. 位置信息
   - 使用目的：用于计算您与门店的距离，推荐最近门店
   - 使用场景：进入门店列表页或预约页时
   - 是否上传服务器：否，仅在本地计算

2. 手机号
   - 使用目的：用于到店预约联系
   - 使用场景：提交预约时授权
   - 存储方式：加密存储于服务器

3. 微信昵称和头像
   - 使用目的：展示顾客个人信息
   - 使用场景：微信登录时获取
   - 存储方式：存储于服务器

4. 预约信息
   - 收集内容：联系人姓名、手机号、预约门店、预约时间、备注
   - 使用目的：到店预约服务
   - 保存期限：预约完成后保留 2 年
```

### 3.2 app.json 隐私配置

```json
{
  "requiredPrivateInfos": ["getLocation"],
  "__usePrivacyCheck__": true
}
```

## 4. 微信小程序提审注意事项

### 4.1 服务类目

当前服务类目可能需要调整。顾客端功能涉及：
- 商品展示 → 可能需要"商家自营-黄金珠宝"类目
- 到店预约 → 可能需要"生活服务"类目

**需在微信后台确认并添加相关类目。**

### 4.2 提审资料

1. 小程序基本信息更新（简介、截图）
2. 隐私协议更新
3. 服务类目确认
4. 测试账号（员工账号 + 顾客测试流程）
5. 功能演示视频（如需要）

### 4.3 审核重点

1. **商品展示**：不涉及交易，纯展示，需说明"商品仅供参考，到店咨询"
2. **预约功能**：不涉及支付，纯预约服务
3. **位置权限**：需说明使用目的，提供拒绝授权后的降级方案
4. **手机号授权**：需说明使用目的，不能强制授权
5. **店长入口**：需说明店长入口不对外公开，需账号密码

### 4.4 审核风险

| 风险点 | 等级 | 应对 |
|--------|------|------|
| 服务类目不匹配 | 高 | 提前提审确认类目 |
| 位置权限被拒 | 中 | 提供降级方案（手动选店） |
| 手机号强制授权 | 高 | 预约时才授权，浏览不需授权 |
| 商品展示被误判为商城 | 中 | 明确标注"到店咨询" |
| 店长入口暴露 | 低 | 放在"我的"页面底部 |
