# 12 - 管理后台「顾客端内容管理」需求规格

> 版本：v1.0（2026-08-15）
> 状态：需求草案，待客户确认后进入 N09 后台改造开发
> 关联文档：06_API_CONTRACT_DRAFT.md、07_DATA_MODEL_DRAFT.md、13_UPLOAD_ASSET_SPEC.md、14_ADMIN_ACCEPTANCE_CHECKLIST.md

## 0. 背景与设计原则

顾客端小程序（miniapp-customer/）当前存在大量前端写死的图片、文案、门店信息、款式信息。本模块的目标是：**顾客端所有可变内容一律来自后台配置，前端不写死**。

设计原则：

1. **复用优先**：后台已有「商品管理」「门店管理」模块，本方案在原模块上**扩展字段**，不新建冲突的数据副本。款式 = 原商品（catalog_products）的顾客端视角，扩展工费等字段。
2. **数据同源**：后台改的内容和顾客端读的内容必须是同一份数据（同一个 config key / 同一张表），不允许出现"后台改了、顾客端不变"的双源结构。
3. **权限收紧**：所有配置接口仅限管理后台 token（`session:` 前缀）+ 对应 ability，顾客 token（`customer_session:`）一律 403。
4. **文案红线**：
   - 首页**不出现**"旧金回收"独立按钮/入口；"旧金回收 / 到店回收"只能作为品牌文案、服务文案出现。
   - "我的"页员工登录入口文案固定为**"店长入口"**，副文案固定为**"门店店长 / 管理员登录"**。全后台不出现"员工入口"字样（作为顾客端可见文案）。
5. 款式详情页底部只允许"咨询门店"和"到店预约"两个动作，**不出现**购买、购物车、支付。

## 1. 后台菜单结构

在现有管理后台（Vue 3）新增一级菜单「顾客端配置」，并扩展原有菜单：

```
├── 顾客端配置（新增一级菜单）
│   ├── 首页 Banner          → Banner 轮播管理（增删改排序、启用禁用）
│   ├── 首页文案             → 品牌标题/副标题/服务文案/核心入口文案/附近门店规则
│   └── 预约须知             → 预约须知富文本 + 我的页服务说明文案 + 客服电话
├── 款式/工费管理（复用原「商品管理」扩展，菜单名可显示为「款式管理」）
│   ├── 款式列表             → 原「商品管理」列表 + 新增列（工费参考/推荐/热门/排序）
│   ├── 款式分类             → 原「商品分类」管理（顾客端款式 Tab 分类）
│   └── 工费说明             → 全局工费说明文案（列表页顶部展示）
├── 门店管理（复用原「门店管理」扩展）
│   ├── 门店列表             → 原列表 + 新增列（门店图片/预约开关/服务标签/排序）
│   ├── 门店图片             → 门店图片上传（在门店编辑抽屉内实现）
│   ├── 门店经纬度           → longitude/latitude 手动填写（不做地址解析强依赖）
│   └── 预约开关             → appointment_enabled per store
├── 预约管理（新增一级菜单）
│   ├── 预约列表             → 全部预约，支持状态/门店/手机号/日期筛选
│   ├── 待确认预约           → 预约列表的 PENDING 视图快捷入口
│   ├── 已确认预约           → CONFIRMED 视图快捷入口
│   ├── 已完成预约           → COMPLETED 视图快捷入口
│   └── 已取消预约           → CANCELLED/NO_SHOW/TERMINATED 视图快捷入口
├── 预约规则配置（顾客端配置下的二级页或独立二级菜单）
│   └── 时段粒度/容量/提前预约/取消限制/可约天数/服务类型
└── 系统配置（复用原系统配置）
    ├── 客服电话
    ├── 隐私协议
    └── 位置权限说明
```

> 实现提示：「待确认/已确认/已完成/已取消」四个菜单项是同一预约列表页的不同 query 预设（`?status=PENDING`），不重复开发。

## 2. 模块一：首页配置

### 2.1 Banner 轮播管理

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | 自动 | banner-{seq} |
| title | string | 是 | Banner 标题 |
| subtitle | string | 否 | Banner 副标题 |
| imageUrl | string(URL) | 是 | 轮播图（上传所得，见 13 号文档） |
| linkType | enum | 是 | `none` / `style_list`（款式列表）/ `style_detail`（款式详情）/ `store_list`（门店列表）/ `store_detail`（门店详情）/ `booking`（到店预约）/ `external_page`（小程序内页面路径） |
| linkTarget | string | 否 | linkType 对应目标：款式 id / 门店 id / 页面路径；none 时留空 |
| sortOrder | int | 是 | 数字越小越靠前，默认 100 |
| enabled | bool | 是 | 启用/禁用，禁用后顾客端不展示 |

约束：启用中的 Banner 最多 8 张；删除前二次确认；linkType 为 style_detail/store_detail 时校验目标存在且有效。

### 2.2 首页文案配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| brandName（品牌标题） | 金匠倌 | 首页品牌区标题 |
| brandSlogan（品牌副标题） | 旧金换打新款 · 包损耗 | 品牌区副标题 |
| serviceCopy（服务文案） | 黄金维修 · 到店回收 · 款式定制 | 服务条文案 |
| entryStyleText（核心入口-款式图） | 款式图 | 首页双入口之一文案 |
| entryFeeText（核心入口-工费） | 工费 | 首页双入口之二文案 |
| nearbyStoreRule（附近门店展示规则） | `{"mode":"distance","count":3}` | mode: `distance`（按定位距离）/ `city`（同城）/ `all`（后台排序）；count: 展示数量 1-5 |
| servicePhone（客服电话） | — | 首页/我的页拨号 |

**红线**：首页配置中**不提供**"旧金回收"独立入口按钮的任何配置项。"回收"相关字样只能出现在 brandSlogan / serviceCopy 文案字段内。

### 2.3 预约须知与我的页文案

| 配置项 | 说明 | 展示位置 |
|--------|------|----------|
| appointmentNotes | 预约须知（多行文本） | 到店预约页底部、我的页「预约须知」 |
| serviceIntro | 服务说明文案（多行文本，可插图） | 我的页「服务说明」 |
| privacyPolicyUrl | 隐私协议链接 | 系统配置（复用） |
| locationPermissionNote | 位置权限说明文案 | 首次请求定位时的说明 |
| 店长入口文案 | **固定值，不可配置**：主文案「店长入口」，副文案「门店店长 / 管理员登录」 | 我的页底部 |

## 3. 模块二：款式/工费管理（复用商品管理扩展）

在现有「商品管理」（`/api/admin/products`，数据存 app_configs `catalog_products`）基础上**扩展字段**：

### 3.1 款式列表新增字段

| 字段 | 类型 | 说明 | 顾客端展示 |
|------|------|------|-----------|
| laborFeeRef | string | 工费参考（如 "35元/克 起"） | 列表卡片 + 详情页 |
| description | string | 款式说明（多行） | 详情页 |
| laborFeeNote | string | 工费说明（多行） | 列表页顶部全局说明 + 详情页 |
| images | []string(URL) | 款式多图（第一张为主图，与原 imageUrl 同步） | 详情页轮播 |
| applicableServiceTypes | []enum | 适用服务类型：OLD_FOR_NEW / REPAIR / CONSULT / RECYCLE | 详情页标签 |
| recommendedStoreRule | enum | 推荐门店规则：`nearest`（离顾客最近）/ `product_stores`（款式关联门店）/ `all` | 详情页"推荐门店"取数 |
| sortOrder | int | 排序，越小越靠前 | 列表顺序 |
| isRecommended | bool | 是否首页推荐 | 首页推荐位（如有） |
| isHot | bool | 是否热门款式 | 列表"热门"角标 |
| status | enum | 上架 active / 下架 inactive（**复用原字段**） | 下架后顾客端不可见 |

### 3.2 保留映射的原字段

name（款式名称）、category/categoryTab（款式分类）、imageUrl（款式主图）、purity、gramWeight、retailPrice、tags、storeIds（关联门店）。

### 3.3 款式分类管理

复用原商品分类：顾客端款式 Tab 的分类列表取自商品 categories。后台需支持：新增/重命名/删除/排序分类。删除分类前校验该分类下无上架款式。

### 3.4 全局工费说明

独立配置项 `customer_fee_note`（多行文本），展示在款式列表页顶部说明区。

### 3.5 详情页动作约束

款式详情页底部按钮**固定**为「咨询门店」（拨打门店电话或客服电话）+「到店预约」（跳预约页，携带款式上下文）。后台**不提供**购买/加购/支付任何配置。

## 4. 模块三：门店预约配置（复用门店管理扩展）

在现有「门店管理」（`/api/admin/stores`，数据存 app_configs `stores`）基础上扩展：

| 字段 | 类型 | 说明 |
|------|------|------|
| imageUrl | string(URL) | 门店图片（新增，原无图片字段） |
| appointmentEnabled | bool | 是否支持预约（新增）。关闭后：该店不出现在预约页门店选择中；已存在的未来预约保留，仅提示到店联系 |
| serviceTags | []string | 门店服务标签（如 "以旧换新" "维修" "定制"） |
| sortOrder | int | 门店排序（nearbyStoreRule=all 时生效） |
| longitude / latitude | float64 | 手动填写，后台提供坐标粘贴输入框（支持"116.404,39.915"批量粘贴），**不做自动地址解析强依赖**；可提供"从地址查询坐标"的辅助按钮（腾讯地图，失败不阻塞保存） |
| contactPhone / businessHours / address / city / status | — | 复用原字段 |

顾客端约束：`status != active` 的门店在所有顾客端页面不可见；`appointmentEnabled=false` 的门店在列表/详情可见但不可发起预约。

## 5. 模块四：预约规则配置（全局）

当前规则在 customer_store.go 中硬编码（09:30-21:30、30 分钟粒度、容量 2、提前 1 小时、7 天、取消提前 2 小时）。改为可配置：

| 配置项 | 默认值 | 校验范围 |
|--------|--------|----------|
| bookableServiceTypes | 全部四种 | 至少启用 1 种 |
| bookableDays | 7 | 1-30 天 |
| slotMinutes | 30 | 枚举 15/30/60 |
| openTime / closeTime | 09:30 / 21:30 | close > open，HH:MM |
| sameDayLeadMinutes | 60 | ≥0 分钟 |
| cancelLeadMinutes | 120 | ≥0 分钟 |
| slotCapacity | 2 | 1-20 |
| 预约须知 | 文本 | 复用 2.3 的 appointmentNotes |

规则变更即时生效（无缓存或改后台配置后清缓存）；已创建的预约不受影响。

## 6. 模块五：预约记录管理

后台预约列表 + 操作（供店长/管理员使用，与员工端 `/api/v1/staff/appointments` 同数据源，管理后台独立路由）：

**筛选**：状态（7 态）、门店、手机号模糊搜索、日期范围、服务类型。

**列表列**：预约号 AppointmentNo、顾客姓名/手机号、门店、日期时间、服务类型、状态、顾客备注摘要、内部备注摘要、创建时间。

**操作**（对应状态机，见 07 号文档第 3 节）：

| 操作 | 允许的当前状态 | 说明 |
|------|---------------|------|
| 确认 confirm | PENDING | 记录 confirmedAt/confirmedBy |
| 标记到店 arrive | PENDING / CONFIRMED | |
| 标记完成 complete | ARRIVED | |
| 取消 cancel | PENDING / CONFIRMED | 需填取消原因；**后台取消不受 2 小时限制**（区别于顾客） |
| 标记未到店 no-show | PENDING / CONFIRMED | |
| 查看/编辑内部备注 | 非终态 | staffNote 字段，顾客端不可见 |
| 查看顾客备注 | 全部 | 只读 |

## 7. 顾客端页面 ↔ 后台配置映射总表（核心交付）

| 顾客端页面 | 可配置内容（后台） | 配置来源 | 对应后台菜单 |
|-----------|-------------------|----------|--------------|
| 首页 | Banner 图/标题/副标题/跳转/排序/启用 | customer_home_config.banners | 顾客端配置→首页 Banner |
| 首页 | 品牌标题/副标题/服务文案/入口文案/附近门店规则 | customer_home_config | 顾客端配置→首页文案 |
| 款式列表页 | 分类 Tab、款式卡片（图/名/工费参考/标签/角标）、排序、上下架、全局工费说明 | catalog_products + 分类 + customer_fee_note | 款式/工费管理 |
| 款式详情页 | 多图、名称、品类、工费参考、款式说明、工费说明、适用服务、推荐门店规则 | catalog_products 扩展字段 | 款式/工费管理→款式列表（编辑） |
| 门店列表/详情页 | 名称、图片、地址、电话、营业时间、经纬度、启用、服务标签、排序 | stores 扩展字段 | 门店管理 |
| 到店预约页 | 服务类型、可约天数、时间粒度、当天提前量、取消限制、时段容量、门店预约开关、预约须知 | appointment_rules + stores.appointmentEnabled | 预约规则配置 + 门店管理 |
| 我的预约/详情 | 状态流转展示（由后台操作驱动）、预约须知 | customer_appointments | 预约管理 |
| 我的页 | 客服电话、服务说明、预约须知；店长入口文案**固定不可配** | customer_home_config / system config | 顾客端配置→预约须知 + 系统配置 |
| 回收介绍页 | 标题/内容/流程/注意事项 | customer_recycle_info（已有） | 顾客端配置（文案归入首页文案或独立 tab） |

**验收底线**：上表"可配置内容"中任何一项，修改保存后顾客端（下拉刷新/重新进入）可见变化；前端代码中不出现这些文案/图片的硬编码常量。

## 8. 权限矩阵

沿用现有 ability 体系（requireAdminAbility），新增两组 ability：

| ability | 说明 | 授予角色 |
|---------|------|----------|
| customer_content.view | 查看顾客端配置（Banner/文案/预约规则） | boss、shop_manager（只读） |
| customer_content.manage | 增删改顾客端配置 | **仅 boss**（super_admin） |
| appointment.manage | 预约记录操作（确认/到店/完成/取消/未到店） | boss、shop_manager（限本店） |

| 角色 | 对应现有角色 | 数据范围 |
|------|-------------|----------|
| super_admin | boss | 全部门店、全部预约、全部配置可写 |
| store_manager | shop_manager | 仅本店预约可操作、本店门店基础资料（图片/电话/营业时间/经纬度/预约开关）可改；款式、Banner、首页文案、预约规则**只读** |
| customer | 顾客 token | 仅顾客端接口 + 本人预约，访问任何 /api/v1/admin/ 或 /api/admin/ 一律 401/403 |
| guest | 未登录 | 仅公开浏览接口 |

门店店长改本店资料复用现有 DataScope + visibleStoreIDs + errUnauthorizedStore 机制。

## 9. 禁止事项清单（开发红线）

1. 顾客端页面不得硬编码图片 URL、品牌文案、服务文案、门店信息、款式数据。
2. 首页不得出现"旧金回收"独立按钮/入口；回收字样仅允许出现在文案字段。
3. 款式详情页不得出现购买/购物车/支付入口。
4. 顾客端可见文案中不得出现"员工入口"，统一"店长入口 / 门店店长 / 管理员登录"。
5. 后台配置接口不得对顾客 token 开放；权限校验必须在后端完成，不依赖前端隐藏。
6. 不重复建设与现有商品/门店管理冲突的第二套数据。

## 10. 决策记录（2026-08-15 客户定案）

| # | 事项 | 定案 |
|---|------|------|
| 1 | 后台接口前缀 | **沿用现有 `/api/admin/`**，不新增 `/api/v1/admin/`；顾客端接口继续 `/api/v1/customer/*` |
| 2 | Banner 数量上限 | 最多 **8 张**（启用中） |
| 3 | Banner 尺寸 | 建议 **750×300**，单张 **≤2MB** |
| 4 | 店长改本店预约开关 | **可以，仅限本店**（visibleStoreIDs 校验，越权 403） |
| 5 | 预约规则变更日志 | **必须记录操作日志**（操作人、时间、变更前后值） |
| 6 | 服务说明形式 | **V1 不做富文本**，多行文本 + 图片；富文本留 V2 |

其余既有红线不变：首页禁止"旧金回收"独立入口；店长入口文案固定；款式详情页底部仅"咨询门店 + 到店预约"。
