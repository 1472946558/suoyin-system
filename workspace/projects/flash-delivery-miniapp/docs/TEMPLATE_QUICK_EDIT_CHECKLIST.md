# 客户快速改造清单

这份清单只针对客户拿到源码后的第一轮修改，目标是先把品牌、文案、接口地址、图片素材、演示数据替换成客户自己的版本，尽快跑出一个像自己项目的可演示版本。

## 建议修改顺序

1. 先改 `utils/config.js`，把项目名、接口域名、客服电话、协议链接换成客户自己的。
2. 再改 `app.json` 和 `app.wxss`，统一导航、TabBar、主色。
3. 然后改 `pages/home`、`pages/order`、`pages/profile`，把演示文案和默认数据改成客户业务。
4. 最后替换 `assets/` 里的图标和 TabBar 图片，确保视觉不再像模板。

## 快速改造明细

| 文件路径 | 要改什么 | 示例 / 说明 |
| --- | --- | --- |
| `app.json` | 全局导航标题 `navigationBarTitleText` | 现在是 `疾蜂急送`，客户如果做鲜花配送，可改成 `花速达`。这是小程序顶部标题，客户一打开就能看到。 |
| `app.json` | 顶部导航颜色 `navigationBarBackgroundColor`、文字颜色 `navigationBarTextStyle` | 现在是深色头部 `#101114`。如果客户品牌是绿色系，可改成 `#0E7A46`，同时保留 `white` 文字保证可读性。 |
| `app.json` | TabBar 文字和图标路径 | 当前 5 个 Tab 是 `首页 / 下单 / 跟踪 / 订单 / 我的`。如果客户不需要“跟踪”，不要只改文字，必须同步调整 `pagePath` 和对应图标。 |
| `app.json` | `pages` 页面顺序 | 首页默认是数组第一个页面。客户如果想首屏直接进下单页，可以把 `pages/order/index` 提到第一位，但要确认演示流程是否仍成立。 |
| `app.wxss` | 全局品牌色变量 `--brand`、`--brand-strong`、`--brand-deep` | 当前主色是黄橙色。可按客户品牌改，例如医药配送可换成 `--brand: #2BB673; --brand-strong: #14935A; --brand-deep: #0D5C39;`。改这里可以一次影响按钮、标签、高亮。 |
| `app.wxss` | 全局背景和文字色 `--ink`、`--bg`、`--paper` | 如果客户要求更亮或更商务，可以直接调这几项，不要逐页乱改。第一轮先全局改，速度最快。 |
| `app.wxss` | 通用组件样式 `.primary-btn`、`.dark-hero`、`.card` | 客户最容易关注按钮和首屏大卡片。比如品牌要更稳重，可以把 `.dark-hero` 的渐变改成品牌深蓝，按钮阴影减弱。 |
| `utils/config.js` | `appName`、`brandSlogan` | 这是全局项目身份。示例：`appName: "花速达"`，`brandSlogan: "30 分钟鲜花专送"`。建议先改，后续页面文案更容易统一。 |
| `utils/config.js` | `mode` | 演示阶段用 `mock`，连客户服务器时改成 `production`。改完后，下单页提示文案会自动从“本地演示环境”切到“已连接客户服务器”。 |
| `utils/config.js` | `apiBaseUrl` | 现在是占位地址 `https://api.your-domain.com`。必须替换成客户正式或测试域名，例如 `https://delivery-api.client.com`。 |
| `utils/config.js` | `tenantId` | 如果后端按租户区分客户，这里要填客户自己的租户编码，比如 `huasuda-sz`，避免多个客户共用演示数据。 |
| `utils/config.js` | `servicePhone`、`privacyUrl`、`userAgreementUrl` | 这是最容易被客户忽略、但验收时会被问到的内容。先填真实客服电话和正式协议链接，不要继续保留占位域名。 |
| `utils/config.js` | `endpoints` 各接口路径 | 要跟客户后端对齐，不要默认认为 `/api/v1/orders` 可直接用。重点核对 `createOrder`、`listOrders`、`orderDetail`、`estimatePrice`、`login`。 |
| `pages/home/index.js` | 首页演示地址 `fromAddress`、`toAddress` | 当前是深圳示例地址。客户如果做上海同城配送，第一时间改成真实城市示例，不然一眼就像模板。 |
| `pages/home/index.js` | 指标数据 `metrics` | 当前是 `30min / 1v1 / 24h`。可按客户业务换成 `45min 达 / 全城覆盖 / 夜间可下单`。这些数字比口号更影响客户感知。 |
| `pages/home/index.js` | 场景数据 `scenes` | 当前是文件、鲜花、数码、生鲜。客户如果做宠物跑腿、蛋糕配送、商超代送，优先改这里，因为首页“常用急送”是最显眼的业务入口。 |
| `pages/home/index.js` | 服务承诺 `promises` | 当前强调“专人直送、过程可见、价格透明、商用可扩展”。可改成客户自己的卖点，比如“冷链保温、夜间加急、企业月结、签收拍照”。 |
| `pages/home/index.js` | 流程步骤 `flow` | 当前是“填写地址 -> 智能估价 -> 骑手接单 -> 全程追踪”。如果客户有预约下单、客服确认等环节，这里要同步调整。 |
| `pages/home/index.wxml` | 首页大标题和副标题 | 当前文案是 `一单一送，准时抵达`。鲜花场景可改成 `鲜花蛋糕，准时送到`；企业文件场景可改成 `票据合同，专人即取即送`。 |
| `pages/home/index.wxml` | 按钮名称 | `立即下单`、`客服咨询` 这两个按钮可直接改成客户业务话术，例如 `马上寄件`、`联系调度`。 |
| `pages/home/index.wxml` | “价格预估”“服务保障”等区块标题 | 如果客户暂时没有估价能力，可以把“价格预估”改成“费用参考”，避免客户误以为一定是实时后端报价。 |
| `pages/order/index.js` | 下单品类 `itemTypes` | 第一轮必须改成客户真实业务支持的品类，不然用户下单项和后端实际分类会对不上。示例：`["鲜花", "蛋糕", "礼品", "同城文件", "其它"]`。 |
| `pages/order/index.js` | 重量选项 `weights` | 如果客户按件数、箱数、车型计费，不要继续保留 `1kg以内` 这种重量逻辑，应替换成例如 `["小件", "中件", "大件", "超大件"]`。 |
| `pages/order/index.js` | 表单默认值 `form` | 如果客户要求新用户下单时默认带城市、默认备注模板，可在这里预置。比如备注默认写 `请提前电话联系收件人`。 |
| `pages/order/index.js` | `demoNotice` 提示文案 | 这是客户现场演示时经常会被看到的说明。建议改成更像项目自己的话，例如 `测试环境订单仅用于验收，不会触发真实骑手派单。` |
| `pages/order/index.wxml` | 表单标签与 placeholder | 例如 `取件地址`、`收件地址`、`物品类型`、`备注`。如果客户是帮买帮送业务，可改成 `购买门店`、`送达地址`、`商品类型`、`代买要求`。 |
| `pages/order/index.wxml` | 提交按钮文案 | `提交订单` 可以按业务改成 `立即呼叫骑手`、`确认寄件`、`提交配送需求`。 |
| `pages/order/index.wxml` | 估价模块标题与展示逻辑文案 | 如果客户想弱化价格，把 `ESTIMATE` 改成 `费用参考`；如果价格由客服二次确认，可加说明 `最终以客服确认报价为准`。 |
| `pages/profile/index.js` | 访客态名称和说明 `displayName`、`displaySubtitle` | 当前是 `商用急送账户`。可改成 `花速达会员`、`企业配送中心` 等，让“我的”页不再像通用模板。 |
| `pages/profile/index.js` | 统计数据 `stats` 默认值 | 当前有 `优惠券 3`、`地址 2` 的演示数字。客户若没有这些能力，建议先改成 `0`，避免演示时被追问来源。 |
| `pages/profile/index.js` | 功能菜单 `menus` | 当前有 `常用地址 / 优惠券 / 在线客服 / 企业月结`。可改成 `售后服务 / 发票申请 / 配送范围 / 商家合作` 等客户真实入口。 |
| `pages/profile/index.wxml` | 合规提示文案 | 底部现在提示补充隐私政策、用户协议、平台资质、客服机制。若客户已有这些资料，可替换成品牌化话术，或引导到真实协议页。 |
| `pages/account/index.js` | 演示填充按钮 `fillDemo()` 里的假数据 | 这里最容易露出模板痕迹。姓名、手机号、公司、默认地址要全部替换成客户自己的测试资料，至少换成客户所在城市。 |
| `pages/account/index.js` | 登录提交提示 | 如果客户不是“登录/注册”逻辑，而是“提交资料”“申请开通”，要同步把 `submitText` 和成功提示文案换掉。 |
| `pages/orders/index.js` | 订单列表报错提示 `errorText` | 可以改成更贴近客户业务的说法，例如 `订单同步失败，请稍后重试或联系客服。` |
| `pages/order-detail/index.js` | 详情页失败提示与跳转逻辑 | 如果客户没有“轨迹”页，可以把 `goTrack()` 对应入口隐藏或改成跳客服，不要保留空页面链路。 |
| `assets/tabbar/*` | TabBar 图标全部替换 | 当前图标风格统一，但仍是模板视觉。第一轮至少把 5 个 TabBar 图标替换成客户品牌版本，保持命名不变可减少代码改动。 |
| `assets/ui/*` | 场景图标、客服图标、价格图标等 UI 资源替换 | `document.png`、`flower.png`、`support.png`、`price.png` 这些都直接出现在核心页面。改完客户的视觉辨识度会立刻提升。 |
| `assets/` | 品牌素材命名规范 | 最省事的做法是沿用原文件名直接覆盖，比如新图继续命名为 `support.png`。这样不用改代码，适合客户第一轮快速替换。 |

## 第一轮最容易漏改的地方

| 文件路径 | 要改什么 | 示例 / 说明 |
| --- | --- | --- |
| `utils/config.js` | 占位域名和协议链接 | 只改了页面文案但没改 `apiBaseUrl`、`privacyUrl`、`userAgreementUrl`，演示时一点击就会露馅。 |
| `pages/account/index.js` | 演示客户资料 | `fillDemo()` 里的 `廖先生`、`13800002026`、`疾蜂急送测试客户` 很显眼，建议第一轮就替换掉。 |
| `pages/home/index.js` + `pages/home/index.wxml` | 城市与业务类型不一致 | 比如客户做北京鲜花配送，但首页还写“深圳试运营”“文件证件”，会直接影响专业感。 |
| `pages/profile/index.js` | 功能菜单与真实能力不一致 | 页面写了“优惠券”“企业月结”，如果客户暂时没有这些功能，先改成中性入口，避免销售演示时被追问。 |
| `assets/tabbar/` | 图标没换 | 代码文案改完但图标还没换，整体看上去仍然像模板，客户通常会立刻注意到。 |

## 客户第一轮改完后的自检

1. 打开首页，确认项目名、城市、核心业务场景已经是客户自己的。
2. 进入下单页，确认品类、地址提示、按钮文案、价格说明已对齐客户业务。
3. 进入“我的”页，确认账户名、菜单项、合规提醒不再出现模板措辞。
4. 断网或改错接口地址试一次，确认报错文案不会出现明显模板名称。
5. 全部 TabBar 和首页核心图标看一遍，确认没有残留旧品牌视觉。
