# Admin 管理端目录说明

本目录用于承载黄金回收小程序配套的后台前端工程。当前项目口径已经明确为“微信小程序 + 独立后台管理端 + 支付能力 + 模板化交付”，因此后台不应塞进小程序端，而应作为单独的 Web 管理台建设。

## 当前定位

- 面向角色：老板主控台为主，店长可按权限进入受限运营台。
- 第一阶段目标：优先交付登录、首页、门店、账号、角色权限等核心骨架，并预留支付配置、支付流水、系统配置、模板初始化入口。
- 权限原则：前端只识别能力码和数据范围，不把权限写死在页面文案或路由判断里。

## 建议首版工程骨架

首版可按以下结构落地：

```text
admin/
  README.md
  src/
    main.ts
    App.vue
    router/
    layouts/
    pages/
    components/
    api/
    permission/
    styles/
    types/
```

各层职责建议如下：

- `layouts/`：后台整体框架，包括侧边菜单、顶栏、门店切换、账号区域。
- `pages/`：页面级视图，按首页、组织权限、业务管理、支付与系统分组。
- `api/`：登录、门店、账号、角色权限、商品、订单、回收单、支付配置、支付流水等接口封装。
- `permission/`：能力码、数据范围、菜单裁剪、路由守卫。
- `types/`：角色、门店、账号、订单、支付配置等领域类型。

## 第一周交付边界

第一周后台前端建议只承诺以下内容：

- 基础工程初始化。
- 登录页。
- 后台首页。
- 门店管理页骨架。
- 账号管理页骨架。
- 角色权限页骨架。
- 支付配置静态页。
- 支付流水静态页。
- 模板初始化入口占位。

不建议第一周就承诺：

- 完整自定义角色系统。
- 复杂报表与经营分析。
- 全量系统配置细项。
- 深度支付联调页面。

## 与其他模块的协作边界

- 小程序端根据能力码和数据范围决定菜单、按钮、页面访问。
- 后端负责真正的鉴权、数据隔离和高风险操作校验。
- 安全与审计要求以操作日志、权限变更留痕、支付相关门禁为准。
