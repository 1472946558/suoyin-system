# 金匠倌小程序业务流程确认稿

日期：2026-06-05

## 一、给客户确认的话术

我们根据您提供的手绘原型，先把小程序首版业务逻辑整理如下，请您确认是否理解一致。

### 1. 底部导航

建议底部导航按以下 5 个入口组织：

1. 首页
2. 商品入库
3. 旧料管理
4. 业务订单
5. 管理

其中第 4 个“业务订单”主要用于统一查看业务单据，不在该页面做录入。

### 2. 首页

首页作为门店员工的工作台，主要展示今日业务概况和常用入口。

首页建议包含：

- 今日收银金额
- 今日回收金额
- 今日订单数量
- 当前门店或员工信息
- 开始收银
- 回收录单
- 商品入库
- 业务订单

### 3. 商品入库

商品入库用于登记门店实际商品库存或新到商品。

入库流程：

```text
商品入库
-> 点击添加
-> 填写款式编号
-> 选择品类
-> 选择成色
-> 填写/选择款式
-> 填写件数
-> 填写重量
-> 确认
-> 入库成功
-> 进入库存管理/库存查询
```

入库字段建议：

- 款式编号
- 品类
- 成色
- 款式
- 件数
- 重量
- 备注

库存管理建议支持：

- 按品类查询
- 按成色查询
- 按款式查询
- 查看件数
- 查看重量
- 文件批量导入库存

需要客户确认：商品入库录入的是“实际库存”，还是只录入“商品款式模板”。如果是实际库存，后续收银成交后需要同步扣减库存。

### 4. 旧料管理 / 回收录单

旧料管理用于黄金回收、旧料登记、回收入库或直接回收留档。

回收录单流程：

```text
回收录单
-> 填写客户信息
-> 选择回收品类
-> 填写品名
-> 填写成色
-> 填写毛重
-> 填写扣减
-> 填写/带出回收单价
-> 上传现场照片
-> 系统计算回收金额
-> 确认
-> 生成回收单
-> 打印小票
-> 进入业务订单
```

回收字段建议：

- 客户姓名
- 客户手机号
- 回收品类
- 品名
- 成色
- 毛重
- 扣减
- 净重
- 回收单价
- 回收金额
- 现场照片
- 备注

旧料业务类型建议分为：

- 直接回收：成交后只生成回收单，不进入在库库存。
- 回收入库：成交后生成回收单，同时进入库存台账。
- 抵押寄存：登记客户抵押物、抵押金额和寄存状态。

旧料管理页面建议包含“今日旧料”和“月度旧料”切换，用于快速查看当天或本月的旧料情况。

旧料汇总表建议字段：

- 序号
- 品类
- 成色
- 重量
- 金额

旧料明细账建议字段：

- 时间
- 大类
- 成色
- 重量
- 回收金额
- 余料

旧料管理建议支持：

- 今日旧料汇总
- 月度旧料汇总
- 旧料明细账
- 按品类统计
- 按成色统计
- 按重量统计
- 按金额统计
- 查看余料

需要客户确认：首版是否需要同时支持“直接回收、回收入库、抵押寄存”，还是先只做“直接回收”；旧料管理里的“金额”和“余料”分别按什么口径计算。

### 5. 商品销售 / 前台收银

商品销售用于门店销售商品并生成收银单。

销售流程：

```text
前台收银
-> 填写客户信息
-> 查询/选择商品
-> 带出商品信息
-> 填写数量或件数
-> 系统计算金额
-> 确认收银
-> 生成收银单
-> 打印小票
-> 进入业务订单
```

销售字段建议：

- 客户姓名
- 客户手机号
- 商品名称
- 商品编号
- 品类
- 成色
- 款式
- 件数
- 重量
- 单价
- 合计金额
- 操作员
- 门店
- 备注

需要客户确认：商品销售是否必须从“库存商品”中选择。如果必须选择，销售完成后库存需要自动扣减。

### 6. 业务订单

业务订单是第 4 个底部导航，用于统一查看业务单据。

业务订单建议包含：

- 收银单
- 回收单
- 单据状态
- 客户信息
- 商品/旧料摘要
- 件数或重量
- 金额
- 门店
- 操作员
- 创建时间
- 订单详情
- 打印小票

筛选查询建议：

- 全部单据
- 收银单
- 回收单
- 待处理
- 已完成
- 按单号搜索
- 按客户姓名搜索
- 按手机号搜索
- 按品名搜索

业务订单不建议承担商品入库功能。商品入库应放在独立入口，业务订单只负责查看和追踪。

### 7. 管理

管理入口用于门店员工和老板查看基础管理能力。

首版建议包含：

- 门店信息
- 员工账号
- 角色权限
- 商品资料
- 库存管理
- 订单记录
- 打印设置
- 系统设置

老板端或后台管理端建议支持：

- 门店管理
- 员工管理
- 角色权限
- 商品管理
- 库存查看
- 订单查看
- 回收留档查看
- 经营统计

### 8. 当前需要客户确认的问题

请您确认以下事项，确认后我们就可以按这个版本继续细化页面和开发范围。

1. 底部导航是否确定为：首页 / 商品入库 / 旧料管理 / 业务订单 / 管理？
2. 商品入库录入的是实际库存，还是商品款式模板？
3. 商品入库里的重量是“单件重量”还是“总重量”？
4. 商品入库是否需要文件批量导入库存？如果需要，请提供导入表格字段。
5. 商品销售是否必须从库存里选择商品？
6. 商品销售完成后是否要自动扣减库存？
7. 旧料管理首版是否只做直接回收，还是同时做回收入库和抵押寄存？
8. 旧料管理是否需要“今日旧料”和“月度旧料”两个统计视图？
9. 旧料汇总表字段是否确定为：品类、成色、重量、金额？
10. 旧料明细账字段是否确定为：时间、大类、成色、重量、回收金额、余料？
11. 旧料里的“余料”指在库旧料余额，还是扣除销售/出库后的剩余重量？
12. 回收现场照片是否固定为 3 张？
13. 回收单和收银单是否都需要打印小票？
14. 业务订单是否只展示收银单和回收单，不包含入库单？
15. 老板是否需要在小程序端看全部门店数据，还是只在后台管理端查看？
16. 员工是否只能查看自己经手的订单，还是可查看本门店全部订单？

## 二、内部执行边界

这部分不建议直接发给客户，用于我们后续开发对齐。

- 第 4 个底部导航应理解为“业务订单”，不是“商品入库”。
- 商品入库、库存台账、回收入库、抵押寄存是独立业务模块，需要客户明确是否本期开放。
- 如果客户确认商品入库本期开放，底部导航和首页入口需要同步调整。
- 如果客户确认商品销售必须走库存，收银单生成后需要增加库存扣减逻辑。
- 如果客户确认入库单也要进业务订单，需要把“业务订单”升级为“业务单据中心”，包含收银单、回收单、入库单。
- 旧料管理不只是回收录单，还包含旧料汇总和旧料明细账；需要和库存台账、回收单列表区分清楚。
- “金额”和“余料”是旧料统计的关键歧义字段，开发前必须让客户确认计算口径。
- 当前客户手绘原型对“品类、成色、款式”的标准选项不完整，需要客户补充枚举。
- 文件导入库存属于批量导入能力，需要确认表格模板和是否本期上线。
