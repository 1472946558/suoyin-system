# 后台管理端信息架构

## 1. 文档目标

本文件用于冻结后台管理端第一阶段的信息架构，供前端、后端、产品和权限联调共用。当前默认口径如下：

- 后台第一版定位为“老板主控台 + 店长受限运营台”。
- 员工默认不进入后台，仍以小程序端操作为主。
- 权限模型采用“固定三级角色模板 + 能力项配置 + 数据范围控制”。
- 前后端统一识别能力码与数据范围，不按页面名称写死权限。

## 2. 角色与后台访问范围

| 角色 | 是否可进后台 | 默认数据范围 | 说明 |
| --- | --- | --- | --- |
| 老板 | 是 | 全部门店 | 主控权限持有者，可配置角色能力、账号、门店、支付和系统项 |
| 店长 | 是 | 本门店 | 受限运营台，可处理本店业务与查看被授权配置 |
| 员工 | 否 | 本人 | 第一版默认不提供后台入口，避免后台复杂度过早膨胀 |

## 3. 菜单结构

建议后台采用左侧一级导航 + 页面内二级标签结构。

### 3.1 一级菜单

1. 首页
2. 组织与权限
3. 商品与业务
4. 支付中心
5. 系统与模板

### 3.2 二级页面归属

| 一级菜单 | 二级页面 | 主要使用者 | 备注 |
| --- | --- | --- | --- |
| 首页 | 后台首页 | 老板、店长 | 经营概览和快捷入口 |
| 组织与权限 | 门店管理 | 老板、店长受限 | 老板看全部，店长仅看本店资料 |
| 组织与权限 | 账号管理 | 老板、店长受限 | 店长仅能管理本店员工，且不能越权授能 |
| 组织与权限 | 角色权限 | 老板 | 第一版关键页面，冻结能力码和数据范围 |
| 商品与业务 | 商品管理 | 老板、店长受限 | 分类、商品基础信息 |
| 商品与业务 | 订单管理 | 老板、店长受限 | 收银订单列表与详情 |
| 商品与业务 | 回收单管理 | 老板、店长受限 | 回收单、图片留痕、状态查看 |
| 支付中心 | 支付配置 | 老板 | 微信支付、现金记账等配置入口 |
| 支付中心 | 支付流水 | 老板、店长受限 | 店长仅看本店流水 |
| 系统与模板 | 系统配置 | 老板 | 拍照规则、编号规则、品牌信息等 |
| 系统与模板 | 模板初始化 | 老板 | 新客户初始化入口，占位即可先上 |
| 系统与模板 | 操作日志 | 老板 | 权限变更、支付配置、账号操作留痕 |

## 4. 页面清单

| 页面 | 页面目标 | 核心内容 | 主要权限 |
| --- | --- | --- | --- |
| 登录页 | 后台身份进入 | 账号密码登录、登录态处理、角色落点 | `auth.login` |
| 后台首页 | 快速总览与跳转 | 今日收银额、订单数、回收利润占位、快捷入口、待处理事项 | `dashboard.view` |
| 门店管理 | 管理门店资料与归属 | 门店列表、门店状态、负责人、营业信息 | `store.view` / `store.manage` |
| 账号管理 | 管理后台可用账号 | 账号列表、角色绑定、门店绑定、启停用、重置密码 | `user.view` / `user.manage` |
| 角色权限 | 老板配置能力项 | 固定角色模板、能力勾选、数据范围配置、预览受影响模块 | `role.view` / `role.manage` |
| 商品管理 | 商品基础维护 | 分类、SKU、价格字段、状态管理 | `product.view` / `product.manage` |
| 订单管理 | 管理收银业务订单 | 订单列表、支付状态、门店筛选、详情抽屉 | `order.view` |
| 回收单管理 | 管理回收业务记录 | 回收单列表、图片数量校验结果、支付记录关联、详情抽屉 | `recycle.view` |
| 支付配置 | 管理支付开关和参数 | 微信支付配置状态、现金记账开关、回调说明、测试状态 | `payment.config.view` / `payment.config.manage` |
| 支付流水 | 查看支付结果与异常 | 交易流水、支付方式、门店、订单关联、回调状态 | `payment.record.view` |
| 系统配置 | 管理全局业务规则 | 回收拍照规则、商品编号规则、小票设置、品牌信息 | `system.config.view` / `system.config.manage` |
| 模板初始化 | 模板开通入口 | 新客户初始化向导占位、默认角色模板、默认门店模板 | `template.init` |
| 操作日志 | 审计高风险动作 | 权限变更、账号启停、支付配置修改、系统配置修改 | `audit.view` |

## 5. 老板权限管理最小功能

第一版不要追求“万能自定义 RBAC 平台”，先做老板可真正用得上的最小闭环。

### 5.1 最小能力集

老板至少能完成以下动作：

1. 创建、启用、停用后台账号。
2. 给账号分配固定角色模板：老板、店长、员工。
3. 给店长或员工绑定所属门店。
4. 在角色模板上勾选能力项开关。
5. 设置数据范围：全部门店 / 本门店 / 本人。
6. 查看谁改过权限、何时修改、修改了什么。

### 5.2 第一版必须开放给老板的能力项

建议以能力码为中心做配置，至少覆盖：

| 能力分类 | 最小能力项 |
| --- | --- |
| 首页 | `dashboard.view` |
| 门店 | `store.view`、`store.manage` |
| 账号 | `user.view`、`user.manage` |
| 角色权限 | `role.view`、`role.manage` |
| 商品 | `product.view`、`product.manage` |
| 订单 | `order.view` |
| 回收单 | `recycle.view` |
| 支付 | `payment.config.view`、`payment.config.manage`、`payment.record.view` |
| 系统 | `system.config.view`、`system.config.manage` |
| 模板 | `template.init` |
| 审计 | `audit.view` |

### 5.3 第一版不建议做的权限能力

- 自定义角色新增与删除。
- 复杂审批流。
- 字段级别超细粒度权限。
- 条件表达式式的数据权限编辑器。
- 多组织树、多品牌、多法人混合授权。

## 6. 页面优先级

### 6.1 第一周必须交付的页面

| 优先级 | 页面 | 交付要求 |
| --- | --- | --- |
| P0 | 登录页 | 可完成登录流程和登录态占位 |
| P0 | 后台首页 | 有基础经营卡片、快捷入口、待办占位 |
| P0 | 门店管理 | 有列表、搜索、详情抽屉或编辑弹窗骨架 |
| P0 | 账号管理 | 有列表、角色绑定、门店绑定、启停用入口骨架 |
| P0 | 角色权限 | 有固定角色模板、能力项分组、数据范围配置骨架 |
| P1 | 支付配置 | 静态表单页，预留微信支付与现金记账配置区 |
| P1 | 支付流水 | 静态列表页，预留门店、时间、支付方式筛选 |
| P1 | 模板初始化 | 入口占位页，表达模板化交付方向 |

### 6.2 第二阶段再补的页面

| 优先级 | 页面 | 原因 |
| --- | --- | --- |
| P2 | 商品管理 | 重要但可晚于组织权限主线 |
| P2 | 订单管理 | 依赖后端业务接口更完整后联调更稳 |
| P2 | 回收单管理 | 依赖附件和状态流设计冻结 |
| P2 | 系统配置 | 依赖更多业务规则口径确认 |
| P2 | 操作日志 | 依赖审计模型与后端日志能力接入 |

## 7. 第一周实现顺序建议

1. 先搭后台通用框架：登录态、布局、菜单、路由、能力码守卫。
2. 再做组织与权限主线：首页、门店、账号、角色权限。
3. 最后补支付中心静态页和模板初始化入口，占住后续联调位置。

## 8. 页面设计约束

- 后台必须是独立 Web 管理台，不与小程序页面混放。
- 菜单显示、按钮显示、路由访问都要走能力码判断。
- 数据范围切换必须体现在筛选条件和默认查询结果中。
- 高风险动作要有二次确认或明显提示，至少包括账号停用、权限变更、支付配置修改。
- 首页指标允许先用占位数据，但结构要能兼容多门店视角。

## 9. 与模板化交付的关系

后台信息架构从第一版起就要考虑复用，因此以下内容不应写死：

- 角色能力项分组。
- 门店组织结构。
- 回收拍照规则。
- 支付方式开关。
- 商品分类与编号规则。
- 品牌名称与基础配置。

这也是为什么第一周优先做“组织与权限骨架”，而不是先堆更多业务页面。
