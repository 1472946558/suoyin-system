# 小程序信息架构

本文档定义黄金回收收银小程序的首版信息架构，覆盖页面清单、推荐导航结构、第一周页面优先级和关键复用组件，供 `ai-weapp`、`ai-backend`、`ai-tech-lead` 对齐开发边界。

## 1. 信息架构原则

- 以门店员工高频操作为中心，优先保证收银和黄金回收双主链路最短可达
- 使用统一路由骨架，不为不同角色拆多套小程序结构
- 页面可见性、按钮可操作性、接口数据范围统一由能力码和数据范围控制
- 多门店切换、支付方式选择、拍照留痕、订单状态展示优先抽成复用能力
- 低频配置能力尽量放入二级页，保持 `tabBar` 聚焦高频任务

## 2. 推荐导航结构

### 2.1 `tabBar`

| 顺位 | 入口 | 页面 | 说明 |
| --- | --- | --- | --- |
| 1 | 首页 | `pages/dashboard/index` | 数据概览、快捷入口、待办提醒 |
| 2 | 收银 | `pages/cashier/create` | 商品选购、会员优惠、收款确认 |
| 3 | 回收 | `pages/recycle/create` | 回收录单、拍照留痕、回收确认 |
| 4 | 订单 | `pages/orders/list` | 收银订单与回收订单统一查询入口 |
| 5 | 我的 | `pages/settings/index` | 账号信息、门店切换、设置与权限入口 |

### 2.2 首页快捷入口

首页建议通过卡片或宫格承载低频但必要的业务入口：

- 会员管理
- 商品管理
- 回收订单
- 支付流水占位
- 门店设置
- 角色权限入口

### 2.3 二级导航关系

```text
登录
└── 首页（工作台）
    ├── 收银开单
    ├── 黄金回收录单
    ├── 会员列表
    ├── 商品列表
    ├── 订单列表
    └── 设置中心
```

## 3. 页面清单

### 3.1 核心页面

| 页面 | 路由建议 | 主要内容 | 主要角色 | 首版优先级 |
| --- | --- | --- | --- | --- |
| 登录页 | `pages/auth/login` | 账号登录、门店上下文初始化、登录错误提示 | 全角色 | P0 |
| 首页/工作台 | `pages/dashboard/index` | 今日收银额、订单数、回收利润占位、快捷入口、待办提醒 | 全角色 | P0 |
| 收银开单页 | `pages/cashier/create` | 商品列表、购物车、会员选择、优惠、备注、支付方式 | 店长/员工/老板 | P0 |
| 收银结果页 | `pages/cashier/result` | 收款成功、支付结果、继续开单/查看订单 | 店长/员工/老板 | P1 |
| 回收录单页 | `pages/recycle/create` | 金料信息、重量纯度报价、客户信息、支付方式 | 店长/员工/老板 | P0 |
| 回收确认页 | `pages/recycle/confirm` | 图片上传、数量校验、金额复核、确认提交 | 店长/员工/老板 | P0 |
| 订单列表页 | `pages/orders/list` | 收银单/回收单切换、筛选、状态、门店范围 | 全角色 | P0 |
| 订单详情页 | `pages/orders/detail` | 订单金额、商品/回收明细、支付流水、附件图片 | 全角色 | P1 |
| 设置中心 | `pages/settings/index` | 当前账号、当前门店、功能入口、退出登录 | 全角色 | P0 |

### 3.2 扩展业务页面

| 页面 | 路由建议 | 主要内容 | 主要角色 | 首版优先级 |
| --- | --- | --- | --- | --- |
| 会员列表 | `pages/members/list` | 搜索、筛选、会员标签、积分/消费记录入口 | 店长/员工/老板 | P1 |
| 会员详情 | `pages/members/detail` | 基本资料、消费记录、回收记录、权益占位 | 店长/员工/老板 | P2 |
| 商品列表 | `pages/goods/list` | 分类筛选、库存/价格展示、编辑入口 | 店长/老板 | P1 |
| 商品编辑 | `pages/goods/edit` | 商品基础信息维护、分类、价格、编号 | 店长/老板 | P2 |
| 门店设置 | `pages/settings/store` | 门店信息、支付方式入口、小票设置占位 | 店长/老板 | P2 |
| 权限设置入口 | `pages/settings/permission` | 权限说明、跳转后台提示、可见能力摘要 | 老板/店长 | P2 |

### 3.3 特殊说明

- 老板、店长、员工不建议拆独立首页路由，建议在 `dashboard/index` 动态下发不同卡片与指标
- 权限深度配置仍以后台为主，小程序仅保留查看当前能力与受限提示
- 如首版要承接真实支付回调结果展示，可在 `orders/detail` 或 `cashier/result` 承接，无需新增支付结果大页

## 4. 第一周页面优先级

### 4.1 第一周必须完成的页面骨架

| 优先级 | 页面 | 目标 |
| --- | --- | --- |
| P0 | `pages/auth/login` | 完成登录页 UI、表单校验、登录态占位 |
| P0 | `pages/dashboard/index` | 完成工作台骨架、指标卡、快捷入口、角色差异占位 |
| P0 | `pages/cashier/create` | 完成收银主流程骨架、购物车、支付方式区块 |
| P0 | `pages/recycle/create` | 完成回收信息录入表单和金额试算骨架 |
| P0 | `pages/recycle/confirm` | 完成图片上传区域与确认栏位 |
| P0 | `pages/orders/list` | 完成订单列表骨架、类型切换、筛选占位 |
| P0 | `pages/settings/index` | 完成账号信息、门店切换、退出与功能入口 |

### 4.2 第一周可以先留静态态的能力

- 收银结果页
- 订单详情页
- 会员列表
- 商品列表
- 门店设置

### 4.3 第一周不建议投入过深的部分

- 自定义复杂筛选器
- 完整会员积分规则
- 商品编辑全表单
- 小程序内完整权限编辑能力

## 5. 关键复用组件

| 组件 | 建议路径 | 复用场景 | 关键说明 |
| --- | --- | --- | --- |
| 权限守卫 | `components/permission-guard` | 控制模块显示、按钮态、无权限提示 | 输入能力码和数据范围，统一处理显隐 |
| 门店切换器 | `components/store-switcher` | 首页、订单列表、设置页 | 支持单店只读、多店切换、当前门店回显 |
| 指标卡片 | `components/metric-card` | 首页数据概览 | 统一金额、订单数、利润占位样式 |
| 快捷入口宫格 | `components/quick-entry-grid` | 首页、设置页 | 根据角色动态渲染入口集合 |
| 搜索筛选栏 | `components/filter-bar` | 订单、会员、商品列表 | 统一搜索、状态筛选、时间筛选交互 |
| 订单状态标签 | `components/status-pill` | 列表与详情 | 区分收银单和回收单状态色 |
| 支付方式选择器 | `components/payment-method-sheet` | 收银、回收 | 第一阶段至少支持微信支付、现金记账 |
| 金额汇总卡 | `components/amount-summary` | 收银、回收确认、详情 | 统一展示应收、实收、优惠、差额 |
| 图片上传器 | `components/photo-uploader` | 回收确认、订单详情预览 | 支持 2-3 张数量校验、删除、预览 |
| 表单分组块 | `components/form-section` | 收银、回收、设置 | 统一标题、说明、字段间距 |
| 空状态 | `components/empty-state` | 列表、搜索结果、无权限场景 | 降低首版大量空数据页面成本 |
| 底部操作栏 | `components/sticky-action-bar` | 收银、回收确认、详情操作 | 固定底部 CTA，兼容安全区 |

## 6. 关键状态与跨页面对象

建议优先统一这些前端对象，避免页面各自定义：

- 当前用户：`userId`、`roleCode`、`capabilityCodes`
- 当前门店：`storeId`、`storeName`、`dataScope`
- 收银草稿单：商品列表、会员、优惠、备注、支付方式
- 回收草稿单：金料信息、重量、纯度、报价、支付方式、图片列表
- 订单筛选条件：订单类型、状态、时间范围、门店

## 7. 与后端联动的架构提醒

- 小程序端只消费能力码，不写死“老板/店长/员工”页面分支
- 回收单附件建议作为独立对象返回，便于详情页和审核页复用
- 支付结果展示需要兼容真实微信支付与现金记账两类链路
- 多门店数据隔离必须体现在首页指标、订单列表、详情访问三个层面

## 8. 结论

首版小程序信息架构建议围绕 5 个 `tabBar` 入口展开，把高频操作压缩到首页、收银、回收、订单四个工作面，把会员、商品、设置类能力沉到二级页。第一周只要完成登录、工作台、收银、回收、订单、设置骨架，就能支撑后续接口联调和权限模型落地。
