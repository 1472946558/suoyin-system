# 需求待补项清单

## 1. 用途

这份文档只记录“已进入范围、但业务口径还没补齐”的需求项，避免这些内容在聊天里反复漂移。

## 2. 必补项

### 2.1 会员模块深度

- 当前已确认要有会员管理。
- 待补口径：
  - 是否只做会员档案、手机号、消费记录
  - 是否加入积分
  - 是否加入等级 / 生日 / 专享折扣

### 2.2 商品与库存

- 当前后台已纳入商品管理。
- 待补口径：
  - 第一阶段是否只做商品资料
  - 是否做库存数量
  - 是否按门店管理库存

### 2.3 回收留痕增强

- 当前已确认拍照留痕是硬需求。
- 待补口径：
  - 是否要身份证照片
  - 是否要客户签字
  - 是否要时间/地点水印
  - 是否要求照片压缩

### 2.4 打印输出口径

- 当前已确认要做小票打印和标签打印。
- 待补口径：
  - 是否强制打印照片缩略图
  - 是否仅打印“照片已留存”摘要
  - 标签是商品标签还是回收标签，还是两者都要
  - 票据宽度、标签尺寸、打印内容字段顺序

### 2.5 店长后台权限

- 当前已确认老板后台控权。
- 待补口径：
  - 店长是否允许进入后台
  - 店长能改哪些内容
  - 店长是否允许查看本店支付流水
  - 店长是否允许修改打印配置

### 2.6 回收支付口径

- 当前已确认支付能力要做。
- 待补口径：
  - 回收支付是实际打款还是仅记录
  - 若实际打款，是否进入统一支付流水
  - 退款 / 撤销 / 冲正是否进入第一期

## 3. 外部条件待补项

- `AppID`
- 商户号与证书
- HTTPS
- OSS `Bucket`
- 打印机型号
- 域名实名认证结果

## 4. 当前处理原则

- 未补齐口径不阻塞骨架开发。
- 但凡涉及数据库字段、接口返回、打印模板结构的项，必须提前留扩展位。
- 若某项会直接改变第一期范围，应回写 PRD，不只留在这份待补项清单里。
