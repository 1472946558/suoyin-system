# PRD：黄金回收收银系统 v2

## 1. 文档原则

这份需求文档按以下优先级整理：

1. 客户已明确提出并反复确认的业务要求排第一。
2. ERPNext 仅作为管理型产品参考，用来补齐模块化、权限、打印、配置化思路。
3. 未被客户确认的增强项，只进入候选或后续版本，不强行塞进第一期。

## 2. 项目背景

客户已确认以现有“黄金收银系统 UI 设计”为视觉起点，开发一套可交付、可复用、可继续卖给后续客户的产品。当前范围已经不是单纯演示原型，而是正式的：

- 微信小程序前台
- 后台管理端
- 后端服务
- 支付能力
- 图片留档
- 多门店与权限体系
- 打印输出能力

## 3. 目标用户

- 老板：看全局数据、开店铺、配权限、看支付与订单。
- 店长：负责本店运营、收银、回收、人员使用与门店内数据。
- 员工：负责录单、收银、拍照、会员服务、日常操作。

## 4. 产品目标

第一阶段交付一套“能真实跑业务”的黄金门店系统首版，而不是仅能演示的 UI。

交付目标：

- 跑通收银与黄金回收两条核心主路径。
- 让老板可在后台控制账号、角色、门店和权限。
- 跑通真实支付接入的系统链路。
- 支持回收拍照留痕，并与订单绑定。
- 支持打印小票与标签的业务输出。
- 产品结构尽量通用，方便后续复制给新客户。

## 5. 客户已确认需求清单（P0）

### 5.1 组织与权限

- 老板自己控制权限。
- 系统至少支持老板、店长、普通员工三级使用关系。
- 组织结构按“老板 -> 多门店 -> 员工”建设。
- 后台权限必须影响：
  - 小程序菜单
  - 页面访问
  - 按钮可见性
  - 接口数据范围
  - 后台页面权限

### 5.2 系统形态

- 微信小程序必须做。
- 后台管理端必须同步做，不是后补。
- 后端服务必须独立建设。
- 第一版就按“模板化产品”思路做，不做一次性定制死代码。

### 5.3 收银与支付

- 收银功能必须是正式模块，不只是静态页面。
- 支付功能要做。
- 第一阶段至少支持：
  - 现金
  - 微信支付
  - 银行卡/转账记账入口
- 后台需要有：
  - 支付配置
  - 支付流水
  - 支付状态查看

### 5.4 黄金回收

- 必须有黄金回收录单流程。
- 确认回收前必须拍照留痕。
- 当前业务口径为：
  - 至少 2 张照片
  - 最多 3 张照片
  - 系统需支持切换为“必须 3 张”
- 图片必须与回收单绑定，并在详情中可查看。

### 5.5 多门店

- 连锁门店场景要支持。
- 老板可看到全局。
- 店长默认只看所属门店。
- 员工默认只看所属门店与被授权功能。

### 5.6 打印能力

- 需要支持小票打印。
- 需要支持标签打印。
- 客户倾向准备两类设备：
  - 小票打印机
  - 标签打印机
- 客户偏好彩色小票机，如果成本与适配允许可优先兼容。
- 客户特别提到：如果入库/回收单有照片，打印输出最好也能带照片或照片摘要。

### 5.7 云资源与上线准备

- 服务器已购买。
- OSS 已准备控制台能力。
- 域名 `jinjiangguan.com` 已购买。
- 域名实名认证/注册局审核仍在处理中，审核通过后才适合继续正式解析与联调。
- 系统上线需要接入：
  - 域名
  - HTTPS
  - 对象存储
  - 小程序主体
  - 商户号

### 5.8 通用化要求

- 代码要做得更通用一点。
- 新客户接入时，尽量通过“开账号 + 配门店 + 配权限 + 配支付 + 配打印模板”即可落地。

## 7. 关键业务流程

### 7.1 收银流程

1. 员工进入收银页。
2. 选择商品、数量、会员、优惠和备注。
3. 选择支付方式。
4. 生成收银订单。
5. 支付成功后写入流水。
6. 支持打印小票。

### 7.2 黄金回收流程

1. 员工创建回收草稿单。
2. 录入金料类型、纯度、重量、回收报价。
3. 上传现场照片。
4. 校验照片数量规则。
5. 确认回收。
6. 生成回收订单。
7. 支持查看订单详情与图片。
8. 按配置决定是否打印凭条/标签。

### 7.3 后台控权流程

1. 老板在后台创建角色或编辑角色能力。
2. 绑定账号到门店。
3. 分配菜单、按钮、数据范围权限。
4. 前后台基于权限集动态生效。

## 9. 明确不直接照搬 ERPNext 的地方

- 客户要的是微信小程序业务系统，不是传统桌面型 ERP 页面。
- 客户最重视回收、拍照、权限、打印、支付，不是全财务全供应链。
- 客户第一期不需要 ERPNext 那种全量模块群。
- 页面交互要以门店一线人员上手快为第一目标。

## 13. 验收标准

- 老板、店长、员工三种身份有清晰权限差异。
- 收银主流程可完整走通。
- 黄金回收主流程可完整走通。
- 回收确认前照片规则有效。
- 后台可配置权限并实时影响前台行为。
- 支付链路、支付流水、订单状态可验证。
- 可输出至少 1 套小票模板和 1 套标签模板。
- 结构具备后续复制给下一个客户的可行性。

## 14. 待补业务口径

以下内容不属于“范围未定”，而是已进入项目但仍需业务补口径的项目，后续必须补齐：

- 会员模块第一期做到什么深度：
  - 仅会员档案与订单关联
  - 还是加积分、等级、生日权益
- 商品模块第一期是否纳入库存数量：
  - 当前先按商品资料 + 售价 + 门店可见性推进
  - 库存精算可放后续
- 回收单是否需要额外留痕：
  - 身份证照片
  - 客户签字
  - 时间水印 / 地点水印
- 打印输出是否强制带照片：
  - 可能是直接打印缩略图
  - 也可能先打印“照片已留存”摘要
- 标签打印内容口径：
  - 商品标签
  - 回收凭条标签
  - 仓储标签
- 后台是否对店长开放部分配置权限：
  - 门店资料可改
  - 打印设置可改
  - 支付配置不可改
