# 客户需求整理纪要

## 1. 这份文档的用途

这份纪要专门记录客户原话所对应的需求，不做技术发挥，避免后面开发被“我们觉得应该这样”带偏。

## 2. 已明确的客户诉求

### 2.1 系统范围

- 做微信小程序。
- 后台一起做。
- 支付一起做。
- 不只做演示，要做成后续能直接给其他客户复用的产品模板。

### 2.2 权限与组织

- 老板自己控制权限。
- 有老板、店长、普通员工层级。
- 支持多门店。
- 权限不仅是账号分级，还包括哪些信息能看、哪些不能看。

### 2.3 黄金回收业务

- 回收流程里要加拍照功能。
- 确认回收前要强制完成拍照。
- 业务讨论中出现两种口径：
  - 至少 2 张最多 3 张
  - 必须 3 张
- 当前产品设计应支持配置，不把规则写死。

### 2.4 收银与支付

- 客户要求把支付做进去。
- 后台需要能看支付相关配置和流水。
- 第一阶段即便外部商户资料暂时未齐，也要把系统链路先搭好。

### 2.5 打印需求

- 需要小票打印。
- 需要标签打印。
- 客户倾向买两类设备分别处理。
- 客户偏好彩色小票输出。
- 客户认为如果业务单据里已有照片，打印结果带照片会更好。

### 2.6 云资源与部署

- 客户已开始购买服务器、域名、OSS。
- 当前已看到：
  - ECS 订单成功
  - OSS 控制台已进入
  - 域名 `jinjiangguan.com` 已买
  - 域名实名认证/注册局审核中
- 这些说明项目正在从“原型”进入“真部署准备”阶段。

### 2.7 通用化方向

- 客户明确说“代码做得通用一点”。
- 这意味着门店、角色、模板、打印、支付和配置项要尽量参数化。

## 3. 客户提出但暂不作为第一期刚需

### 3.1 抖音小程序

- 客户提到以后可能挂到抖音。
- 讨论结论是先不着急，先把微信版本做出来。
- 所以当前只作为后续扩展记录，不进入第一期验收。

## 4. 当前最容易遗漏但必须记住的点

- 这不是通用 ERP 项目，而是黄金门店业务系统。
- 拍照留痕是硬需求，不是装饰功能。
- 老板控权是硬需求，不是系统默认角色展示。
- 打印不是“以后再说”，而是客户已经在准备设备的真实需求。
- 云资源不是空白状态，已经有一部分在推进，文档里要反映进度。
