# ERPNext 对照补齐说明

## 1. 对照原则

- ERPNext 用来参考“模块设计方法”和“管理型产品的成熟做法”。
- 客户原始要求优先级高于 ERPNext 现成模块。
- 只吸收对本项目第一期真正有帮助的部分。

## 2. 可借鉴模块

## 2.1 POS

ERPNext 的 POS 文档强调，零售交易需要把商品、支付、仓库/配置放在同一条流程中处理。本项目可借鉴的不是桌面布局，而是“收银配置先建、收银流程标准化、支付与单据同链路”这套思路。

本项目落地：

- 做门店收银配置
- 做支付方式配置
- 做订单与支付流水关联
- 做打印输出

## 2.2 角色权限

ERPNext 的角色权限体系强调：

- 角色授予
- 文档类型权限
- 字段级权限
- 不同单据阶段权限
- 用户数据范围限制

本项目落地：

- 老板后台可配角色能力
- 按门店限制数据范围
- 按按钮和菜单控制操作权限
- 预留字段级敏感信息控制能力

## 2.3 打印体系

ERPNext 的打印体系比较成熟，核心价值不是“打印”，而是“模板可配置、不同单据可分别输出”。

本项目落地：

- 小票模板
- 标签模板
- 回收单模板
- 后续支持照片摘要/图片区块

## 2.4 看板与模块化

ERPNext 的首页和模块化思路提醒我们，系统不要只堆页面，而要让老板快速看到经营关键项。

本项目落地：

- 后台首页做经营概览
- 做待办项和风险提示
- 做多门店快照

## 3. 不建议照搬的地方

- ERPNext 偏传统 Web ERP，信息密度高，不适合直接搬进小程序。
- ERPNext 模块范围过大，本项目第一期不能被财务、采购、制造等无关模块拖慢。
- ERPNext 的很多概念适合后台，不适合一线店员移动端高频操作。

## 4. 本项目的差异化重点

相对于标准 ERP/ERPNext，本项目更强的定制重点是：

- 黄金回收场景
- 回收拍照留痕
- 门店一线操作效率
- 小票/标签实际打印
- 老板控权
- 微信生态接入

## 5. 结论

ERPNext 适合做“结构参考”，不适合做“需求来源”。本项目第一期应坚持：

1. 先满足客户现有门店业务。
2. 再用 ERPNext 的成熟做法把权限、打印、配置化做扎实。
3. 后续再决定是否继续扩展到更完整的 ERP 能力。
